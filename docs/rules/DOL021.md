# DOL021 — datetime.now() should be timezone.now()

**Default severity:** warning · **Applicability:** suggestion · **Category:** datetime

Detects bare `datetime.now()` calls (the `from datetime import datetime` style; attribute forms like `datetime.datetime.now()` are not matched). `datetime.now()` returns a *naive* datetime in server-local time. With `USE_TZ=True` — Django's default since 4.0 — saving one to a `DateTimeField` triggers `RuntimeWarning: DateTimeField received a naive datetime`, and comparisons against the aware datetimes Django produces elsewhere raise `TypeError`. The idiomatic clock is `django.utils.timezone.now()`, which returns an aware UTC datetime. The QuickFix ("Replace with timezone.now()") rewrites the call only; add the `timezone` import yourself. It is a suggestion because projects that explicitly run `USE_TZ=False` may want naive datetimes.

## Bad

```python
from datetime import datetime

order.confirmed_at = datetime.now()
```

## Good

```python
from django.utils import timezone

order.confirmed_at = timezone.now()
```

## Suppress

```python
# django-orm-lens-disable-next-line DOL021
```

Or per-workspace in `.vscode/settings.json`: `{"djangoOrmLens.rules": {"DOL021": "off"}}`.
