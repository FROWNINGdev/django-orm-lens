# DOL017 — Meta index or unique name breaks the MySQL naming convention

**Default severity:** warning · **Applicability:** suggestion · **Category:** model

Inside `class Meta`, an `Index` (including postgres `*Index`) and a `UniqueConstraint` that already has `name=` must use the name `aicore`'s MySQL schema editor would generate.

The shape is `prefix_<table>_<columns>`:

- `Index` uses the prefix `idx`.
- `UniqueConstraint` uses the prefix `uniq`.
- A `UniqueConstraint` on `uuid` alone is `idx_uniq_<table>`, and that form keeps a leading `ai_`.

`<table>` is `Meta.db_table`. A leading `ai_` is dropped. Each column drops a trailing `_id`. A table longer than 25 characters is compressed, and the whole name stays within 64 characters. A missing `name=` is `DOL016`, not this rule. `CheckConstraint` has no convention here.

The lightbulb replaces the name literal.

The convention is MySQL's. Set `ormSynapse.dbEngine` to `postgres` or `sqlite` to turn the rule off; `auto` (the default) and `mysql` keep it on.

## Bad

```python
class Event(models.Model):
    class Meta:
        db_table = "ai_events"
        indexes = [
            models.Index(fields=["company_id", "status"], name="idx_event_status"),
        ]
        constraints = [
            models.UniqueConstraint(fields=["company_id", "status"], name="unique_event_status"),
        ]
```

## Good

```python
class Event(models.Model):
    class Meta:
        db_table = "ai_events"
        indexes = [
            models.Index(
                fields=["company_id", "status"],
                name="idx_events_company_status",
            ),
        ]
        constraints = [
            models.UniqueConstraint(
                fields=["company_id", "status"],
                name="uniq_events_company_status",
            ),
        ]
```

## Suppress

```python
# orm-synapse-disable-next-line DOL017
models.Index(fields=["company_id"], name="idx_legacy")
```

Or per-workspace in `.vscode/settings.json`: `{"ormSynapse.rules": {"DOL017": "off"}}`.
